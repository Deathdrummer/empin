## Что исправлено

Мобильный вход больше не удаляет все сессии и push-токены пользователя. Новый клиент передаёт постоянный installation_id; повторный вход заменяет только сессию этого устройства. Старые клиенты без installation_id совместимы и также не отключают остальные телефоны. Выход снимает только текущую регистрацию.

Принятие вызова защищено транзакцией и привязано к принявшей сессии. Повторный ответ этого устройства не сбрасывает время разговора; другое устройство того же аккаунта не может повторно принять или завершить активный разговор своим тайм-аутом. RTC-токен формируется до изменения статуса, сбой доставки уведомления не превращает принятый вызов в HTTP 500. Остальные устройства получают адресное событие call_answered_elsewhere.

## Дополнение: устаревший входящий и поздний ответ

По свежей попытке найдено точное объяснение HTTP 422: 01.11 в 21:40:57 принятие вызова 277, отменённого 21:36:50. Журнал содержит Call cannot be accepted; общий Handler подменял текст на «Ошибка валидации». Это не ошибка логина и не доказательство причины ранней отмены: caller завершил этот вызов примерно через секунду, его телефонный журнал недоступен.

Точечно выложен `b22fc6f189c60044332254372a01ee6d5a4b4ac5`: только MessengerCallController и PushNotificationService. Завершённые и непринятые старше 90 секунд вызовы не принимаются; API прямо возвращает JSON call_finished с понятным текстом, не генерирует RTC-токен и не изменяет запись. Для Expo входящего и событий звонка заданы ttl 90 секунд и общий collapseId конкретного вызова, входящий содержит expires_at. APNs VoIP по-прежнему использует apns-expiration=0. Срок доставки и collapseId сверены с официальной документацией Expo: https://docs.expo.dev/push-notifications/sending-notifications/ .

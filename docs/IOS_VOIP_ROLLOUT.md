# Безопасное включение iOS VoIP push

Этот документ описывает будущую выкладку подготовленной интеграции PushKit/CallKit. Он не является командой на автоматическое изменение production.

## Текущее состояние

- Реализация хранится только в локальной ветке `local-ios-voip`.
- На production отсутствуют `ApnsVoipService`, `StaffPushToken` и миграция `staff_push_tokens`.
- APNs-переменные в production `.env` не заданы.
- APNs Auth Key подключён к EAS для обычных Expo push, но на backend не копировался.
- Рабочее дерево production содержит большое количество посторонних незакоммиченных изменений. Нельзя выполнять `git reset`, `git checkout`, `git clean`, pull с перезаписью или массовую синхронизацию.

## Порядок будущей выкладки

1. Согласовать окно и ответственного за production.
2. Сделать отдельную резервную копию только изменяемых файлов, `.env` и базы данных. Записать контрольные суммы копий.
3. Разместить `.p8` вне web-root и репозитория. Каталог должен читаться только пользователем PHP-FPM; рекомендуемые права: `0700` на каталог и `0600` на файл.
4. Проверить ключ локально командой `openssl pkey -check -noout`, не выводя его содержимое.
5. Задать `APNS_VOIP_ENABLED=true`, `APNS_TEAM_ID`, `APNS_KEY_ID`, `APNS_PRIVATE_KEY_PATH`, `APNS_BUNDLE_ID` и `APNS_ENVIRONMENT=production`. Не печатать значения секретов в лог или историю команд.
6. Перенести только перечисленные в Git diff backend-файлы. Не заменять весь каталог приложения и не трогать посторонние изменения.
7. Выполнить `php -l` для каждого изменённого PHP-файла. Проверить существующее состояние config/route cache и не очищать его без необходимости; затем выполнить `php artisan route:list` и целевые тесты.
8. Применить только миграцию `2026_10_05_000000_create_staff_push_tokens_table.php`. Она создаёт новую таблицу и не изменяет существующие таблицы.
9. Проверить регистрацию Expo- и VoIP-токенов, обычные push, входящий звонок, принятие, отказ, отмену и завершение на реальных Android/iPhone.
10. Только после успешного smoke-теста очищать резервные копии; автоматически их не удалять.

## Откат

1. Сразу задать `APNS_VOIP_ENABLED=false`: обычный Expo fallback продолжит работать, а прямые APNs VoIP-запросы прекратятся.
2. Остановить новые регистрации токенов, вернув предыдущие версии маршрутов и контроллера из сделанной копии.
3. Вернуть предыдущие версии `PushNotificationService`, `Staff` и `config/services.php`.
4. Восстановить предыдущий `.env`. Не перезапускать общий PHP-FPM; отдельный reload допустим только после проверки конфигурации конкретного пула.
5. Таблицу `staff_push_tokens` не удалять в аварийном откате: она не влияет на старый код и сохраняет данные для расследования. Удалять её можно только отдельным согласованным действием после резервной копии.
6. APNs Auth Key на Apple Developer не отзывать. При необходимости достаточно убрать путь из backend-конфигурации и отвязать credential в EAS.

## Критерии допуска

- PHP-синтаксис и маршруты проверены на версии PHP, совпадающей с production.
- Provisioning profile содержит `aps-environment=production`.
- Сборка iOS компилирует локальный модуль `EmpinVoip` и не содержит Firebase iOS SDK.
- Проверены минимум два реальных устройства и состояния foreground, background, locked и terminated.
- В логах нет содержимого `.p8`, push-токенов или других секретов.

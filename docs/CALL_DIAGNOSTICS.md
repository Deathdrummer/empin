# Трассировка звонков мобильного приложения

TraceMessengerCall применяется только к POST initiate/accept/reject/cancel/end после auth:sanctum. Остальные API и веб не трассируются. Бизнес-логика и схема БД не меняются.

Локальный журнал сервера: `storage/logs/mobile-calls-YYYY-MM-DD.log`. Отдельный Laravel daily logger, права 0600, хранение 7 дней. Настройки default/Telegram/Slack logger не используются. Ошибка создания/записи журнала не меняет результат API.

Поля: время сервера в Unix ms, request_id для пары request/response, call_id, action, actor_staff_id, числовой ID personal_access_tokens (не токен авторизации), build/platform, временный client_session и числовой cause. До/после фиксируются только статус, caller_id, callee_id; сохраняются HTTP-статус, длительность и класс исключения. Тексты исключений, заголовки Authorization, тела запросов, адреса, имена, push/Agora-токены и содержимое разговора не пишутся.

Клиентские заголовки X-Empin-Build / X-Empin-Platform / X-Empin-Call-Session / X-Empin-Call-Cause необязательны и очищаются. Старые клиенты совместимы: actor/session по авторизации сервер узнает и без обновления, build/cause/client_session будут null. Клиентская причина диагностическая, не доказательство намерения пользователя и не участвует в авторизации.

Локальный клиентский JSON: Профиль → Диагностика звонков → сохранить/поделиться. 400 последних событий, UTC-время, последовательность seq, временный session запуска, номер сборки, ID попытки и RTC-движка, вызов leaveChannel с причиной, SDK-коды соединения, микрофона и подписки на удалённое аудио. Отчёт передаёт сам пользователь через системное меню; автоматической отправки файла нет.

Основные cause: 1 — кнопка завершить; 2 — отклонить; 3/4 — тайм-аут входящего/исходящего; 5 — SDK peer offline; 6 — RTC failure; 7/8 — ошибка initiate/accept; 9/10 — WebSocket/push окончания; 11 — API уже закончил вызов; 12/13 — CallKit end/timeout; 14 — Android native end; 15/16 — logout/unmount; 17/18 — замена движка/локальный reset; 19/20 — устаревший ответ initiate/accept; 30 — нет доступа к микрофону; 31 — другой звонок уже идёт. Полная карта включена в JSON клиента.

Для расследования взять один call_id, сопоставить server actor_staff_id + access_token_id с build/platform/client_session, найти client event end-command/reset-command/rtc-leave-command и его cause, затем события SDK до него. Уход участника, работа подписки или факт HTTP accept не доказывают слышимость голоса. У старого клиента отсутствие cause не позволяет установить, какая его кнопка/ветка вызвала end; серверный actor покажет, с чьей сессии пришёл запрос.

Проверки: серверные тесты различают завершающее устройство, контролируют очистку секретов/заголовков и отказ журнала. Клиентские тесты проверяют очистку и ограничение истории, обработку повреждённого JSON, SDK-аудиособытия и защиту от запоздавших событий.
